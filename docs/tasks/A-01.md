## Goal

Later survival checks need named scenarios instead of one hard-coded smoke flow. Add a small registry in tools/pumpkin-compat so a scenario is a named function that receives the connected client and the running server process. Keep the existing smoke scenario as the first entry. Do not change what smoke asserts.

## Files and crates

- `tools/pumpkin-compat/src/scenario.rs`
- `tools/pumpkin-compat/src/lib.rs`
- `tools/pumpkin-compat/src/bin/pumpkin-compat.rs`

## Acceptance criteria

- pumpkin-compat smoke still runs the current login, chunk, place, and dig flow.
- A second named scenario can be selected from the binary without copying the process launcher.
- The ignored smoke test still passes when PUMPKIN_BIN is set.

## Verification

cargo test -p pumpkin-compat --lib and the existing pumpkin_smoke ignored test. vanilla_milestones stays green.

## Out of scope

- New gameplay.
- Downloading a vanilla world.
- Editing pumpkin-protocol.
