## Goal

`/scoreboard objectives add kills dummy "Kills"` stores the display name with the quote characters, and vanilla shows Kills. `/team add` does the same. Both commands take the display name with `StringArgumentType::GreedyPhrase`, which keeps the quotes, then wrap that string in `TextComponent::text`. Vanilla parses this argument as a text component. Use the existing `ComponentArgumentType`, the same one `tellraw` and `title` use. It already strips quotes and accepts a JSON component.

## Files and crates

- `crates/pumpkin-core/src/command/commands/scoreboard.rs` (`ObjectivesAddExecutor`, the `objectives add` branch)
- `crates/pumpkin-core/src/command/commands/team.rs` (`TeamAddExecutor`, `add_branch`)
- `crates/pumpkin-command/src/argument_types/component.rs` (use it, do not rewrite it)

## Acceptance criteria

- After `scoreboard objectives add kills dummy "Kills"`, the objective display name's plain text is `Kills`, with no quote characters.
- After `team add red "Red"`, the team display name's plain text is `Red`, with no quote characters.
- `scoreboard objectives add kills dummy {"text":"Kills"}` stores that component, not the raw JSON string.
- An objective or team added with no display name still uses its own name as the display name.
- A dispatcher parse of both commands consumes the whole line and reports no errors.

## Verification

Unit tests next to the dispatcher tests in `scoreboard.rs`, and the same style in `team.rs`. Parse with `CommandSource::dummy`, read the component argument, and assert the plain text. `cargo test -p pumpkin-core --lib command::commands::scoreboard` and the new team test.

## Out of scope
