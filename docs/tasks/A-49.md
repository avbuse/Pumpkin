## Goal

Vanilla 26.3 logs `Failed to parse saved data for 'SavedDataType[minecraft:game_rules]'` when it loads a Pumpkin world. `game_rules_to_nbt` puts `DataVersion` inside the `data` compound. Vanilla wants that int on the root, beside `data`. `write_weather` and `write_wandering_trader` in the same file already do that. A-05 moves `world_clocks.dat` the same way, and `write_world_clocks` is the sibling writer, so wait until A-05 has left `data_files.rs`. Do not copy `write_world_clocks` if it still nests the int.

## Files and crates

- `crates/pumpkin-world/src/world_info/data_files.rs` (`game_rules_to_nbt`, `write_game_rules`, `game_rules_from_nbt`)
- `crates/pumpkin-world/src/world_info/anvil.rs` (the `rewrite_level_dat_stamps_current_version` assertion)

## Acceptance criteria

- A written `game_rules.dat` has `DataVersion` as an int on the root compound, and the `data` compound does not contain `DataVersion`.
- `data` still holds the `minecraft:` rule entries.
- `rewrite_level_dat_stamps_current_version` expects the root int.
- A file shaped like vanilla, with `DataVersion` only on the root, still loads the rule values.
- A file Pumpkin already wrote, with `DataVersion` only inside `data`, still loads the rule values.

## Verification

Unit test around `game_rules_to_nbt` and `game_rules_from_nbt` with synthetic NBT. No Mojang world in git. The existing anvil rewrite test covers the path through `write_world_info`.

## Out of scope

- `world_clocks.dat`. A-05 owns that writer.
- `world_gen_settings.dat`, which still nests `DataVersion` inside `data`.
- Changing rule values or the gamerule command.
