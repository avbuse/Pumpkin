## Goal

`/team join red Steve` fails with "No entity was found" when Steve is offline. `TeamJoinExecutor` resolves members with `EntityArgumentType::Entities`, and an unknown name becomes `argument.entity.notfound.entity`. Vanilla takes a score holder here. An offline name, a fake name such as `#temp`, and a name that is not a logged-in player are stored as that string. Use the existing `ScoreHolderArgumentType`. `ResolvedScoreHolder::resolve_name` already keeps a name literal when no online player matches. `team leave` uses the same entity argument and the same error. Switch that members argument too.

## Files and crates

- `crates/pumpkin-core/src/command/commands/team.rs` (`TeamJoinExecutor`, `TeamLeaveExecutor`, `join_branch`, `leave_branch`)
- `crates/pumpkin-core/src/command/argument_types/score_holder.rs` (use it, do not add a second name parser)

## Acceptance criteria

- `team join red Steve` parses, and resolving the members argument with no online player named Steve yields the literal name `Steve`.
- The result is not `argument.entity.notfound.entity`.
- The team `red` then contains `Steve`.
- `team join red` with no members still targets the sender.
- A selector such as `@a` still resolves to online entities only.
- `team leave Steve` accepts the same offline name and removes it when it is on a team.

## Verification

A dispatcher test in `team.rs`. Parse `team join red Steve` with `CommandSource::dummy` (no server, so nobody is online), read the members argument through `ScoreHolderArgumentType::get_score_holders`, and assert the name is `Steve`. That test fails while the node is still `EntityArgumentType`. `cargo test -p pumpkin-core --lib command::commands::team`.
