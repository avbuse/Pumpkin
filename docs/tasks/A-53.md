## Goal

`PlayerDataStorage::save_player_data` opens the live `<uuid>.dat` with `File::create` and writes into it. A crash mid-write, or a rejoin that reads during the logout save, leaves a short file. The next join treats that player as new.

26.3 does not write the live file in place. `PlayerDataStorage.save` creates a temp file in the player directory, named with the player id as a prefix. The compressed player tag is written to that temp file through an output stream opened with the sync flag, so the bytes are on disk before the stream is closed. `Util.safeReplaceFile` then deletes any existing `<uuid>.dat_old`, moves the live `<uuid>.dat` onto that backup name, and moves the temp file onto `<uuid>.dat`. If the temp file cannot take the live name, the backup is moved back. The move is a same-directory rename. `PlayerDataStorage.load` reads `<uuid>.dat` first. When that file is missing or the read throws, it reads `<uuid>.dat_old`. A failed read of a file that is still present is also copied to a dated name before the backup is tried. That dated copy, and the ten retries around each delete and move, are not part of this task.

Match the replace itself: write a temp file in the same directory, fsync it, rename it onto the live file, keep the previous file as `<uuid>.dat_old`, and load the backup when the live file is corrupt or missing. Hold a per-player lock across the save and across the load so two saves cannot interleave and a rejoin cannot observe the gap between the two renames.

## Files and crates

- `crates/pumpkin-world/src/data/player_data.rs`

## Acceptance criteria

- A save writes a temp file in the player directory, fsyncs it, and renames it onto `<uuid>.dat`. The temp file is not left behind after a successful save.
- The previous `<uuid>.dat` is kept as `<uuid>.dat_old`.
- A truncated `<uuid>.dat` loads the backup compound. The truncated file is left as it was.
- A missing `<uuid>.dat` with `<uuid>.dat_old` present loads the backup.
- Concurrent saves and loads of the same player never return a partial compound, and never report the file missing once a save has finished.
- Saving still does nothing when player data saving is disabled.

## Verification

Unit tests in `player_data.rs`. One truncates the live file after two saves and asserts the first compound comes back. One removes the live file and asserts the same fallback. One runs saves and loads on the same id and asserts every load is a complete compound. `cargo test -p pumpkin-world --lib data::player_data`.

## Out of scope

- Player NBT fields. A-06 owns `player.rs` and `saved_nbt.rs`.
- The dated copy 26.3 makes of a corrupt live file, and the ten retries around the replace.
- Other in-place writers. They do not share this helper without their own backup read path:
  - `level.dat` in `crates/pumpkin-world/src/world_info/anvil.rs` already writes `level.dat_new`, copies the live file to `level.dat_old`, and renames. The read path does not open the backup. Startup in `server/mod.rs` also copies a good `level.dat` onto `level.dat_old`.
  - `write_weather`, `write_world_gen_settings`, `write_game_rules`, `write_world_clocks`, `write_wandering_trader`, `write_custom_boss_events_stub`, `write_scheduled_events_stub`, `write_random_sequences_stub`, `write_scoreboard`, `write_world_border`, `write_scoreboard_stub`, and `write_stopwatches_stub` in `data_files.rs` truncate the destination with `File::create` and do not keep a backup.
  - Region writes in `chunk/format/anvil.rs` and `chunk/format/linear.rs` rename a temp file and do not keep a backup. `poi/mod.rs` writes in place.
