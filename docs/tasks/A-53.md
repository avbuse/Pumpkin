## Goal

`PlayerDataStorage::save_player_data` opens the live `<uuid>.dat` with `File::create` and writes into it. A crash mid-write, or a rejoin that reads during the logout save, leaves a short file. The next join treats that player as new.

26.3 does not write the live file in place. `PlayerDataStorage.save` creates a temp file in the player directory, named with the player id as a prefix. The compressed player tag is written to that temp file through an output stream opened with the sync flag, so the bytes are on disk before the stream is closed. `Util.safeReplaceFile` then deletes any existing `<uuid>.dat_old`, moves the live `<uuid>.dat` onto that backup name, and moves the temp file onto `<uuid>.dat`. If the temp file cannot take the live name, the backup is moved back. The move is a same-directory rename. `PlayerDataStorage.load` reads `<uuid>.dat` first. When that file is missing or the read throws, it reads `<uuid>.dat_old`. A failed read of a file that is still present is also copied to a dated name before the backup is tried. The ten retries around each delete and move are not part of this task.

Match the replace itself: write a temp file in the same directory, fsync it, rename it onto the live file, keep the previous file as `<uuid>.dat_old`, and load the backup when the live file is corrupt or missing. When that backup load succeeds, move the corrupt live file aside (or delete it) so the next save does not rename it onto `<uuid>.dat_old`. Hold a per-player lock across the save and across the load so two saves cannot interleave and a rejoin cannot observe the gap between the two renames.

A periodic snapshot is taken on the tick and written later. If the player logs out in between, that older snapshot must not replace the logout save. Each snapshot takes the next per-player sequence, and a write older than the last one stored for that player is skipped. Periodic snapshots are also skipped once the player has left. The per-player gate is removed after the leave save, once nothing is still in flight. The disk write on leave and on a full save runs in `spawn_blocking`.

## Files and crates

- `crates/pumpkin-world/src/data/player_data.rs`

## Acceptance criteria

- A save writes a temp file in the player directory, fsyncs it, and renames it onto `<uuid>.dat`. The temp file is not left behind after a successful save.
- The previous `<uuid>.dat` is kept as `<uuid>.dat_old`.
- A truncated `<uuid>.dat` loads the backup compound. The truncated file is moved aside, so the next save does not rename it onto `<uuid>.dat_old`.
- A snapshot taken before a newer save does not replace that newer file when the older write runs second.
- After a leave save, the per-player gate is gone. A later write for that id does not recreate it and overwrite the file.
- A missing `<uuid>.dat` with `<uuid>.dat_old` present loads the backup.
- Concurrent saves and loads of the same player never return a partial compound, and never report the file missing once a save has finished.
- Saving still does nothing when player data saving is disabled.

## Verification

Unit tests in `player_data.rs`. One truncates the live file after two saves and asserts the first compound comes back, the short file is moved aside, and a following save leaves the backup as that first compound. One removes the live file and asserts the same fallback. One runs saves and loads on the same id and asserts every load is a complete compound. One writes a newer sequence and then an older one and asserts the newer compound remains. One marks the player left and asserts a later write does not replace the file. `cargo test -p pumpkin-world --lib data::player_data`.

## Out of scope

- Player NBT fields. A-06 owns `player.rs` and `saved_nbt.rs`.
- The ten retries around the replace. A corrupt live file is moved aside under a dated `.corrupt` name, which is the same idea as 26.3's dated copy, but the live path is cleared so the next save cannot keep the corrupt bytes as `<uuid>.dat_old`.
- Other in-place writers. They do not share this helper without their own backup read path:
  - `level.dat` in `crates/pumpkin-world/src/world_info/anvil.rs` already writes `level.dat_new`, copies the live file to `level.dat_old`, and renames. The read path does not open the backup. Startup in `server/mod.rs` also copies a good `level.dat` onto `level.dat_old`.
  - `write_weather`, `write_world_gen_settings`, `write_game_rules`, `write_world_clocks`, `write_wandering_trader`, `write_custom_boss_events_stub`, `write_scheduled_events_stub`, `write_random_sequences_stub`, `write_scoreboard`, `write_world_border`, `write_scoreboard_stub`, and `write_stopwatches_stub` in `data_files.rs` truncate the destination with `File::create` and do not keep a backup.
  - Region writes in `chunk/format/anvil.rs` and `chunk/format/linear.rs` rename a temp file and do not keep a backup. `poi/mod.rs` writes in place.
