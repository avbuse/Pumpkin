## Goal

When the server moves a client back to configuration, vanilla sends the registry and tag data again and waits for the finish acknowledgement. Pumpkin only stores ConnectionState::Config. Follow the same sequence the initial configuration path already uses, so a client that is reconfigured can return to play.

## Files and crates

- `crates/pumpkin-core/src/net/java/play/configuration_acknowledged.rs`
- `crates/pumpkin-core/src/net/java/config/`

## Acceptance criteria

- A client that receives a start-configuration packet gets registry data again and can finish configuration.
- The first join path still sends registries once.
- A client that never acknowledges does not stay half-configured without a timeout.

## Verification

A harness scenario that, after play starts, triggers reconfiguration if the server can be asked to do so from the console or a test hook. If there is no public trigger, add the smallest test-only hook and document it.
