# A-06 playtest

A survival player who logs out and comes back after a restart keeps the same health, hunger, inventory, spawn point, and gamemode.

Use a 26.3 Java client on a new world. The default gamemode is survival, and the account you join with can run operator commands.

## Checklist

1. Join. Expect full health, a full hunger bar, an empty inventory, and survival (no flying, and you can take damage).
2. Run `/give @s diamond 3` and `/give @s iron_helmet`. Put one diamond in the off-hand and wear the helmet. Put one emerald in an ender chest.
3. Run `/damage @s 7`. Expect the health bar to drop by three and a half hearts.
4. Sprint and jump until the hunger bar loses at least one shank. Run `/data get entity @s Health` and `/data get entity @s foodLevel` and write both numbers down. After step 7 those two commands must report the same numbers.
5. Stand on a block you can recognize, away from world spawn. Select hotbar slot 4. Run `/spawnpoint @s ~ ~ ~ 270 120`. The command feedback may print yaw 270 and pitch 120. `/data get entity @s respawn` must show `yaw` -90, `pitch` 90, `forced` true, and `pos` on that block. The compound has `dimension`, `pos`, `yaw`, `pitch`, and `forced`. It must not contain `angle` or `SpawnX`.
6. Run `/gamemode creative`, then `/gamemode survival`. You should be in survival again.
7. Disconnect. Stop the server with `stop`. Start it again in the same directory and rejoin.
8. Expect the same health, the same hunger, three diamonds with one of them in the off-hand, the iron helmet still worn, the emerald still in the ender chest, and hotbar slot 4 still selected.
9. Expect survival: hearts are not full if you left them low, you cannot fly, and blocks break at survival speed. `/data get entity @s respawn` still shows yaw -90 and pitch 90.
10. Die in a hole or with `/kill`. Expect to respawn at the spawnpoint from step 5, facing the same way as yaw 270 and looking steeply up (pitch 90). Item drops on death are A-27 and are not part of this check.
11. Set `/gamemode adventure`, disconnect, stop, start, and rejoin. Expect adventure: no block breaking and no flight. `/data get entity @s playerGameType` is 2. Then `/gamemode creative`, disconnect, stop, start, and rejoin. Expect creative, including flight. `playerGameType` is 1. Set survival again before you leave. `previousPlayerGameType` is not updated by `/gamemode`; F3+F4 having nothing to restore is a separate gap, not a fail of this list.

## Missing player file

Stop the server, delete that player's file under `world/players/data/` (the `<uuid>.dat` from the logout), and start again. Do not delete `world/players/advancements/`. Rejoin. Expect a new survival player: full health, full hunger, an empty inventory, no personal spawnpoint, and survival gamemode.

A clean `stop` must not log `Failed to read player data`. The file is written in place, so a hard kill during the logout save can truncate it and load a new player. That result after `kill -9` is a known separate gap. The same result after a clean `stop` fails this list.
