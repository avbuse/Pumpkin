# A-53 playtest: crash-safe player saves

Use an operator on a new world. Player files are `world/players/data/<uuid>.dat` and `world/players/data/<uuid>.dat_old`, next to the server's working directory. The backup appears on the second successful save. A periodic save is five minutes, so use disconnect instead of waiting.

1. `/give @s diamond`. Disconnect.
   Expect `world/players/data/<uuid>.dat` to exist and `<uuid>.dat_old` to be absent.

2. Rejoin.
   Expect the diamond. `/give @s emerald`. Disconnect again.
   Expect both `<uuid>.dat` and `<uuid>.dat_old`.

3. Stop the server. Replace `<uuid>.dat` with a file that is only a few bytes. Start the server and rejoin.
   Expect the diamond from step 1, and no emerald. You do not spawn as a new empty player. The log has a warning that the player data is unreadable and the backup is being tried. The short `<uuid>.dat` is still the short file.

4. Disconnect and rejoin twice, without editing files.
   Expect the inventory from step 3 both times (diamond, no emerald). The second disconnect writes a fresh `<uuid>.dat`.

5. While holding the diamond, run `stop` from the console so the logout save finishes. Start the server and rejoin.
   Expect the diamond.
