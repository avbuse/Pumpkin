# A-50 playtest: scoreboard and team display names

Display names on `/scoreboard objectives add` and `/team add` are text components. A quoted name stores the text inside the quotes. A JSON component stores that component. Omitting the name stores the objective or team name. The value is the same `TextComponent` the A-05 scoreboard save already writes for 26.3: plain text is a string tag, and a styled component is a compound tag.

Use an operator on a new world. The chat line is the check. The unit tests do not draw chat or team colors. `objectives list` and `objectives setdisplay` are A-51, so the sidebar does not show the objective yet. `team modify displayName`, `prefix`, and `suffix` still take a raw string. Do not fail this list because those three keep the quote characters.

1. `/scoreboard objectives add kills dummy "Kills"`
   Expect `Created new objective Kills`. The word Kills has no quote characters.

2. `/scoreboard objectives add styled dummy {"text":"Kills","color":"gold"}`
   Expect `Created new objective Kills`, with Kills in gold. The chat does not show the JSON text.

3. `/scoreboard objectives add plain dummy`
   Expect `Created new objective plain`.

4. `/team add red "Red"`
   Expect `Created team Red`, with no quote characters.
   `/team list` expects one team and the name Red, not `"Red"`.
   `/team list red` expects `There are no members on team Red`.

5. `/team add blue {"text":"Blue","color":"blue"}`
   Expect `Created team Blue`, with Blue in blue.
   `/team list` shows Blue in blue, not the JSON text.

6. `/team add green`
   Expect `Created team green`.
   `/team list green` expects `There are no members on team green`.

7. Stop the server and start it again. `/team list`
   Expect Red, Blue, and green with the same display names as steps 4, 5, and 6. Blue is still blue. A restart reads the shared `scoreboard.dat` from A-05.

Capture: a recording of steps 1, 2, 4, and 5, including the chat text and the color on Kills and Blue.

## Automated

From the repo root, after a debug build:

```bash
cargo test -p pumpkin-core --lib command::commands::scoreboard
cargo test -p pumpkin-core --lib command::commands::team
```

`objectives_add_parses_display_name_as_a_component` and `team_add_parses_display_name_as_a_component` parse with `CommandSource::dummy`. The whole line is consumed, `errors` is empty, and the component's plain text is `Kills` or `Red`. The JSON form is not stored as the raw JSON string. A gold JSON name equals that component.

`objectives_add_without_display_name_parses_the_whole_line` and `team_add_without_display_name_parses_the_whole_line` accept the command with no display-name argument. The executors still use the objective or team name in that branch.

`parsed_team_display_name_uses_the_shared_scoreboard_save` writes `Scoreboard::to_nbt` at `MAXIMUM_SUPPORTED_WORLD_DATA_VERSION` (5023, the 26.3 data version) and reads it back with `Scoreboard::from_nbt`. That is the compound `load_scoreboard` stores in `scoreboard.dat`. `team add red "Red"` saves the team `DisplayName` as the string tag `Red`. Objective display names use that same writer. This branch does not add a second round trip for them.

Also run:

```bash
cargo build --workspace
cargo clippy -p pumpkin-core --all-targets --all-features
cargo fmt --check
```

## Out of scope

- `objectives list` and `objectives setdisplay` (A-51).
- `team join` (A-52).
- `team modify displayName`, `prefix`, and `suffix`. They stay greedy strings.
- The scoreboard NBT reader and writer. This task only feeds them a real text component.
