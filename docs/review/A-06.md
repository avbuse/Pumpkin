## Cleanups

1. **Non-vanilla keys on save.** `write_spawn_point` writes the 26.3 `respawn` compound. Vanilla `RespawnConfig` is `dimension`, `pos`, `yaw`, `pitch` and `forced`. The function also writes `angle` and the legacy `SpawnX` / `SpawnY` / `SpawnZ` / `SpawnAngle` / `SpawnDimension` / `SpawnForced` keys. Vanilla ignores them, but nothing needs them: reading old files stays in `read_legacy_spawn`. Drop the extra writes.
2. **Yaw range.** Vanilla's codec is `Codec.floatRange(-180, 180)` for `yaw` and `(-90, 90)` for `pitch`. A value outside that range makes vanilla drop the whole `respawn` entry. Wrap yaw into -180..180 before writing.
3. **Leniency that nothing needs.** `read_food_level` accepts int, byte, short or float. `read_saved_item_stack` accepts a float `count`. `saved_item_slot` accepts an int `Slot`. Vanilla writes one type for each. AGENTS.md asks not to add fallbacks for cases that cannot happen. Keep the types vanilla writes, plus the byte `Slot` it uses.

## Found while testing, not caused by this branch

- **Player files are written in place.** `PlayerDataStorage::save_player_data` (`crates/pumpkin-world/src/data/player_data.rs`) does `File::create` and then writes. During one run, a rejoin landed while the logout save was being written. The server logged `Failed to read player data ... NBT reading was cut short: unexpected end of file`, and that player loaded as new. A crash mid-write would do the same. Vanilla writes a temp file and renames it. This is worth its own small task, since this branch is about player data surviving.
- **`previousPlayerGameType` is never set.** The line that should record it on a gamemode change is commented out (`player.rs` around 4881). So `/gamemode` never saves the previous mode, and the F3+F4 switcher has nothing to go back to. Also a separate task.
