# Review notes: A-16 bed spawn

Reviewed at `21e7047`, merged locally onto `core-functionality` `70a0b84`. Delete this file in the commit that addresses it.

**Status: needs rework before merge.** The branch builds, clippy is clean, and the tests pass. But the main behaviour change is the opposite of vanilla 26.3, and so is the task file it follows.

## 1. Blocking: vanilla sets the spawn before the time and monster checks

`ServerPlayer.startSleepInBed` in the 26.3 server jar runs in this order:

1. Out of range: `TOO_FAR_AWAY`.
2. Blocked above: `OBSTRUCTED`.
3. **If the bed rule can set spawn, `setRespawnPosition(...)` runs here.**
4. Then `!canSleep` returns the rule's problem (daytime is `NOT_POSSIBLE_NOW`).
5. Then, outside creative, monsters in the 8 x 5 x 8 box return `NOT_SAFE`.

So a daytime click, or a click with a monster nearby, still sets the respawn point in vanilla. Players see "Respawn point set". `decide_bed_sleep` only sets the spawn on `Sleep { set_spawn: true }`, which drops that. The code on `core-functionality` before this branch got this order right.

Fix:
- Set the spawn when the bed is in range, not obstructed, and `can_set_spawn` holds, before the `can_sleep` and monster checks.
- Update `docs/tasks/A-16.md`. Its acceptance line "Sleeping in the daytime does not set the spawn" contradicts vanilla, which is where this came from.
- Update the playtest checklist to match.

## 2. Monster check uses the wrong set of mobs

Vanilla collects `Monster.class` entities in the box and keeps those where `monster.isPreventingPlayerRest(level, player)` is true. `entity_category_prevents_bed_rest` uses `MobCategory::MONSTER` instead. Checked against the jar:

- Slime and magma cube extend `AbstractCubeMob` (an `AgeableMob`).
- Ghast and phantom extend `Mob`.
- Shulker extends `AbstractGolem`.

None of these are `Monster`, so in vanilla they do not stop sleep. With this branch they do, because they are in the monster category.

`ZombifiedPiglin` overrides `isPreventingPlayerRest`: it only blocks while angry at that player.

Match the class hierarchy rather than the spawn category. The old hardcoded list was also wrong (it had phantom and ocelot), so do not go back to it.

## 3. Check order and messages

Vanilla checks range before obstruction. `decide_bed_sleep` checks obstructed, then occupied, then range. A player who is both too far away and blocked sees a different message than in vanilla. The occupied check belongs to `BedBlock` before `startSleepInBed`, which is fine. Only range and obstructed are swapped.
