# Review notes: A-42 predicates

Reviewed at `e1fb788`, merged locally onto `core-functionality` `70a0b84`. Delete this file in the commit that addresses it.

**Status: needs a design change before merge.** The branch builds, clippy is clean, and the tests pass. The loader works. The problem is that it adds a second condition model.

## 1. A second condition model next to the loot one

`crates/pumpkin-core/src/data/datapack/loot_table_loader.rs` already parses loot conditions into `DynamicLootCondition` (`crates/pumpkin-util/src/loot_table.rs`). That covers `match_tool`, `entity_properties`, `any_of`, `all_of`, `inverted`, `weather_check`, `table_bonus` and more.

This branch adds `predicate_loader::Predicate` with its own `match_tool` and `entity_properties` parsing and its own `test` methods. Predicate files and inline loot conditions are the same JSON in vanilla (`LootItemCondition`), and AGENTS.md asks for one pattern per job.

- Parse predicate files into the existing condition type, extending it where it is too coarse.
- Add the `minecraft:reference` condition so loot tables and advancements resolve predicate ids through `get_predicate`.

Note that the existing `match_tool` parsing is string-matching on `"silk_touch"` / `"shears"`. If you need a real item predicate, improve that one type rather than adding a parallel one.

## 2. A warning on every boot for vanilla content

Vanilla ships three predicate files. `minecraft:block/fast_cooking` uses `minecraft:match_block`, which is unsupported. So every boot logs:

```
WARN Skipping predicate 'minecraft:block/fast_cooking': unknown type 'minecraft:match_block'
```

I saw this on every boot of the test server. Admins cannot fix it. Either support `match_block` (it is small), or log embedded vanilla files at `debug` and keep `warn` for user datapacks.

## 3. Nothing reads the predicates yet

`get_predicate` has no caller. That is consistent with the playtest note, where A-43 and A-44 wire it in. Say that in the PR, so reviewers do not look for a consumer.

## Smaller points

- `load_pack_contents` checks both `predicate/` and `predicates/`. Vanilla 26.3 uses `predicate/` only. Drop the plural unless a real pack needs it.
