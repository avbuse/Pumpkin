## 1. Datapack loot that references a predicate now never drops

`parse_condition` now turns a string pool condition, or `{"condition":"minecraft:reference","name":...}`, into `DynamicLootCondition::Reference(id)`. `world/loot.rs` resolves a `Reference` through `LootContextParameters::predicate_lookup`. Nothing sets that field yet ("A-43 and A-44 supply this"), so every `Reference` evaluates false.

This only affects loot tables loaded from datapacks. Vanilla block drops use the generated static tables. But for those datapack tables it is a behaviour change on merge:

- Before this branch, a datapack table whose pool used a predicate reference passed that condition, because the string was not understood.
- After it, the pool never drops.

So a pack that overrides a block's loot with `"condition": "minecraft:tool/can_silk_touch"` would stop dropping anything.

Since this branch introduces `Reference`, wire it in this branch. Set `predicate_lookup` from `server.datapack_manager.get_predicate` where the block, entity and chest loot contexts are built. It is a few lines. A-43 and A-44 can then use the same lookup for advancements.
