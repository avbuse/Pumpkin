## The fix

The root cause is right. `tools/pumpkin-codegen/src/block_transformer.rs` read `blocks.json` as a map of top-level keys. The real shape is `{ "blocks": [ { "name": ... } ] }`, so every transformer rule failed the "valid block" filter and the generated `AXE` / `SHOVEL` / `HOE` tables were empty.

Reading the list fixes stripping, pathing and tilling from the extracted vanilla data, with no hardcoded maps. `block_transformer_tests.rs` exercises the generated tables (oak log keeps its axis, copper scrape and wax-off, door halves, path and till face rules, coarse and rooted dirt), so it would have caught the empty tables. These are the right kind of test.

## Follow-ups

1. **Shield in the off hand.** Vanilla returns `PASS` from `transformBlock` when the main hand is used, the off hand has `BLOCKS_ATTACKS` (a shield), and the player is not sneaking (`playerHasBlockingItemUseIntent`). That way right-click raises the shield instead of stripping the log. `axe.rs` does not check this, so a player holding a shield strips logs when they mean to block. Add the same check to the axe, shovel and hoe paths.
2. **Copper chest neighbour.** Vanilla does not set the other half of a double copper chest in the transformer. It only sends the game event and particle there. The other half follows through `CopperChestBlock.updateShape`, which copies the new block onto the connected half. Setting it directly in `axe.rs` gives the same end state. Moving that into the copper chest's neighbour update would mirror vanilla and also cover a chest changed by other means, such as `/setblock`.
3. **Scope.** The branch also reworks door handling and adds copper chest support in `axe.rs`. Both are fine. List them in the PR, since the task only named logs, paths and farmland.
